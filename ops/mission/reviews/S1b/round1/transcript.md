## New findings, most severe first
- **K25 (High): C5 and C6 are "verified" with no judge.** `claims.json` maps C5 to P2-G5 and C6 to P3-G5. Both are the same `e2e_prod.sh` as P0-G5. `required.json` has no `a2-layout` or `a2-a11y` family, and `registered.py` only checks judge files that exist. If `rerun_all` ran today, C5 and C6 would come out verified because the existing suite passes.
- **K26: the family minimums of 1 are decoration.** C1–C3 rest on specific specs. Several of them (`share-code`, `share-lookup`, `creator-v2`, `studio-polish`) belong to no required family. Deleting or renaming a test is invisible to the gate, because only skips are frozen.
- **K27: the second phase run always fails.** `loop.py` `pulse()` writes `ops/mission/state-of-the-union.html` after every `run-gates`. That file is not in `.gitignore` and not on `prod_server.sh`'s exempt list. From the second run on, `e2e_prod` exits 4, which is reported as falsified (band 1), and no merging phase can pass.
- **K28:** the part of K15 that was not repaired (above).
- **K29: retrying until green is not prevented.** The contract says a failed gate is a loopback, never a retry until green. `merged_scan` accepts any green run at a head, including one that follows a red run at the same head.
- **K30: the merged result is never tested.** The merge rule asks only that GitHub report "mergeable", not that the branch be up to date with main. Nothing checks that main's tip before the merge is an ancestor of the PR head.
- **K31: the review base is the lead's choice.** `review_closed.py` accepts any `base` written in the dispositions, so a narrowed diff can still close a round.
- **K32: the WebKit, AAC and cloud gates don't judge their reports.** A spec whose tests all skip passes, and C2b, C4 and C8 would then count as verified. `aac_publish.sh --project=chromium` names a project that doesn't exist, so a capable Chromium would wrongly falsify C2b.
- **K33: C9's live check can't come out falsified.** If `merged_scan` fails, C9 is reported "unverified" whether the cause was a real violation or `gh` being unavailable.
- **K34 (judgement): provenance of the review and C9 records.** The seat records and the ledger are files the lead writes, and both the hash chain and `transcriptSha256` only prove internal consistency. Contract §3's "not the lead's copy" overstates what the gate checks. Either report these as advisory, or anchor them to GitHub CI.
- **Lows (K35–K40):**
  - K35: merge rules 2 (CI green) and 3 (deployment serving the merge SHA) have no gate.
  - K36: the cloud URL pattern also accepts a host that merely starts with production's.
  - K37: the hitl footer string doesn't match the real attribution line.
  - K38: review files are read from the working tree, so a green run can rest on uncommitted records.
  - K39: the seat's tool set is broader than `seat.sh` says.
  - K40: nothing enforces that a judge is registered before its phase's first fix.
