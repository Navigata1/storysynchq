## Deviations from the reference / ticket and why
1. **The cassette label's sizes follow s01, not the bare `.ss-cassette`.**
   - What follows s01: field padding 7px 14px, title 6.9cqi (21px at 340px), meta 3px under the title in `--ss-ink-2` at 0.16em.
   - Why: with the base `.ss-tape__meta` 12px margin, the meta line ran 3px under the window's top edge at the hero's 368px width.
   - Title and meta are single-line with an ellipsis, because the window covers the label's lower half. The band keeps the `.ss-cassette__label` 10px. s01 bumps it to 11px; T06 can do that per screen if it wants.
2. **The publish-card consumer check is label-scoped.** At 375px the Studio *underneath* the publish card already scrolls sideways: `scrollWidth` 386. The Transport row is the cause: four 60px transport buttons, gaps, padding, and an 86px readout. This was traced with a scratch probe: `section` `sw=386 cw=375` → `div.w-[86px]` in `Transport.tsx`.
   - It is not a label. It is in the Studio lane (`Transport.tsx`, not owned here). No label code can fix it.
   - So the publish-card phone test asserts every label sits inside [0, 375], plus the full label alignment. The page-scroll assertion stays on for every other consumer (`/read`, end card, teaser, `/protocol`, the cover, the hero).
   - This is listed under Left open.
3. **One alpha literal is kept in `.sk-tape-field`.** The ticket itself fixes the rule line "at `rgba(30,26,22,.07)`", which is the ink token at 7%, and kit.css's convention keeps alpha tints of a token as rgba until a later ticket names them. Every *other* colour in the changed rules is a token:
   - the `.sk-tape` shadow is now `color-mix(in srgb, var(--ss-slot) 60%, transparent)`;
   - the meta rule's old `rgba(30,26,22,.14)` is gone;
   - the reel face falls back to `color-mix(in srgb, currentColor 7%, transparent)`, where `currentColor` is `--sk-ink` and defaults to `--ss-ink`.
4. **Reel face default.** The reference `#i-reel` defaults to a paper face, and screens on chrome override it to navy (`--reel-face: #1b2033`). The kit keeps a faint tint of the ink as the default and sets paper only in tape-stock contexts (the Cassette window). This is because 9 existing reel consumers sit on dark chrome with light `--sk-ink` (Transport, Stage, deck chip, ReadRoom loading, PublishCard, the Player shell, `/protocol` reels, the landing doors), and a paper default would have turned them into white discs. The rim, dash, spokes and hub geometry is the reference's everywhere.
5. **Reel strokes now scale with the reel** (the reference's behaviour), instead of `vector-effect: non-scaling-stroke`. Small reels get proportionally thinner strokes. The 18px deck-chip reels draw a 0.72px rim, as the 18px reels in s06 do.
6. **Extra test coverage** beyond the five named tests: chooser accents, the end card, the teaser, `/protocol`, the phone hero, the 4b rest frame, reel geometry, and the Node token checks.

## Decision log entry
**2026-10-25 · T05b · Tape stock is one implementation: TapeLabel inside Cassette; reels rest at 18°; reel face is contextual.** The kit `Cassette` (`studio-kit/Cassette.tsx` + `cassette.css`) renders the reference `.ss-cassette` and uses the kit `TapeLabel` for its label (class `sk-cassette-label`), so the band, holes, "STORYSYNC", title and meta can never drift between a label and a cassette. The cassette is `aria-hidden` and scales internally with container units. `Reel` draws the reference `#i-reel` geometry. Its spin keyframes start at 18°, so a reel at rest or under reduced motion sits on the reference's static 18° frame. Its face is `--sk-reel-face`: paper in tape-stock contexts (the Cassette window), and a faint ink tint by default so reels on studio chrome keep reading light-on-dark. `Reel.size` accepts a CSS length as well as px.
