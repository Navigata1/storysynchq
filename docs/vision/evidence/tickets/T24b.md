## What was built

### `src/lib/audio/moods.ts` (additive `explainMood`)
- `explainMood(value)` → `{ mood: MoodName | null; matched: string | null }` (exported `MoodExplanation`). `mood` is
  always `resolveMood(value)`; `matched` is the normalised mood name or synonym that decided it ("lullaby" for "a quiet
  lullaby for bedtime"), or `null` for the house-default Wonder (no known word) and for silence (empty, punctuation only,
  not a string).
- `resolveMood(value)` is now `explainMood(value).mood`: one decision path, so the two can never disagree. Its
  signature and documented contract are unchanged; `tests/critic-melody.spec.ts` and `tests/wp-melody.spec.ts` pass
  unchanged.
- Bug fixed on the way (see Deviations): the vocabulary lookup now reads **own keys only** (`lookupWord`). Before,
  `resolveMood("constructor")` and `resolveMood("a constructor of joy")` returned `Object` (the prototype's
  constructor function) instead of a mood; typed into the new field that would have crashed the pill. Both now resolve
  as the contract says: Wonder, and Joy.

### `src/components/studio/Inspector.tsx` (the TYPE A FEELING row)
- `FeelingRow`, in Mix directly after T24a's MOOD row (s09's order: MOOD, TYPE A FEELING, ACTIVITY, the voice switch).
- Label "Type a feeling" (rendered TYPE A FEELING: mono 10.5 px, uppercase) for `#insp-feeling`: `type="text"`,
  placeholder "a quiet lullaby for bedtime", `maxLength` 80, `autocomplete="off"`, `spellcheck="false"`,
  `aria-describedby="insp-feeling-note"`, the kit focus ring (`sk-focus`).
- As the parent types, the answer follows after a 150 ms debounce (≤ 200 ms): an arrow (lucide `ArrowRight`, hidden from
  assistive tech) and the result pill `[data-studio="feeling-result"]` with `aria-live="polite"`: the kit's mood icon
  (`MOOD_ICON` from T22a's `MoodTapeChip.tsx`, e.g. lucide Cloud for Hush) and the mood's name, outlined in its
  `--mood-*` colour on a 20 % fill (`data-mood` names it). The pill is never focusable. It stays mounted while empty
  (zero size, nothing drawn) so its live region speaks from the first word.
- With a non-empty input and `matched === null`: the pill reads "Wonder" and the 11.5 px muted line
  `[data-studio="feeling-note"]` (polite live region) reads "No feeling word we know — Wonder is the house default."
  With an understood word the line is empty and takes no room.
- Two actions under the line, side by side, 44 px tall: **"Use for page N"** (`data-studio="feeling-page"`) and **"Use for
  every page"** (`data-studio="feeling-every"`), both disabled while the input resolves to nothing (empty or
  punctuation only). Enter in the input does what "Use for page N" does. Both act on the words as they are at that
  moment (not the debounced pill), so Enter straight after typing applies what was typed.
- The typed words live only in this component's state: closing Advanced drops them; nothing writes them anywhere.

### `src/components/studio/feeling.css` (new, `@layer components`)
- `.feeling-label`, `.feeling-line`, `.feeling-input` (dashed white/18 border on black/30, italic words, as s09's
  `.s9-in`; 44 px like every other Inspector control), `.feeling-arrow`, `.feeling-pill` (`--c` = the mood token;
  `border: 1px solid var(--c)`, `color-mix(… 20%, transparent)` fill, text `color-mix(… 55%, #fff)` as the reference's
  `.ss-mood`; height 28, padding 0 12 0 9, 600 13 px, gap 7; `:empty` takes no room), `.feeling-note` (11.5 px,
  `--ss-fg-3`; `:empty` takes no room), `.feeling-actions` (two equal columns, gap 8).
- Nothing animates, so reduced motion has nothing to remove.

### `src/components/studio/Studio.tsx` (wiring only)
- `applyFeelingToPage(mood)`: T24a's `setPageMood(mood)` for the active page, then the polite announcement
  "Page N is <Mood> now.".
- `applyFeelingToEveryPage(mood)`: the story `mood` and `pageMoods: {}` (exactly the Music card's T24a choice), then
  "Every page is <Mood> now.".
- The Studio's existing polite live region gains `data-studio="announcement"` (a test hook; no behaviour change).

## Deviations from the reference and the ticket

1. **Two explicit apply buttons** ("Use for page N", "Use for every page") instead of the reference's single arrow: the
   reference does not say which pages the arrow applies to (ticket-sanctioned).
2. **The house-default line** under the pill for words it does not know (M5-PRD open question 5; ticket-sanctioned).
3. **No "Next" chip** on the row (built items carry none; ticket-sanctioned).
4. **The pill is outlined on a 20 % fill with the mood's icon**, not s09's filled `.ss-mood.is-on` with an ink dot: the
   ticket specifies the outlined form and the kit icon set (T22a) so the pill reads as an answer, not a selected chip.
5. **Control heights**: the input and the buttons are 44 px like every other Inspector control (s09 draws a 30 px input);
   touch targets on the phone's sheet. The words are 14 px italic (s09: 12.5 px italic), matching the Inspector's other
   inputs.
6. **The state in the fidelity shot**: the whole-story select reads Wonder (the house tape's story mood) while s09's
   reads Hush; the ticket's state is "typed, Hush shown", i.e. before applying.
7. **`resolveMood` own-key fix** (the ticket says `resolveMood` is untouched): its contract is unchanged, but
   `"constructor"` (and any phrase whose longest word it is) used to return `Object` instead of a mood name; it now
   returns what the documented contract says (Wonder / the phrase's real mood word). Without the fix a parent typing
   "constructor" would crash the pill (`MOOD_ICON[Object]`), and the Player's music plan would receive a function for a
   manifest `music: "constructor"`. No existing test changes.

- **T24b · `explainMood` is `resolveMood` showing its work.** `src/lib/audio/moods.ts` exports `explainMood(value) →
  { mood, matched }`; `resolveMood` returns `explainMood(value).mood`, so the two share one decision path. `matched` is
