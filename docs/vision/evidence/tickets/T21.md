## What was built

### `src/components/player/resume.ts` (new, pure, relative imports only)
- `RESUME_KEY = "ssync-resume"` holds `{ v: 1, tapes: Record<key, { page, of, at }> }` and nothing else.
- `tapeKey(manifest, openedCode?)`, in this order:
  - `code:<code>` from the tape's own `signature.shareUrl` `?story=` value;
  - else `code:<openedCode>`;
  - else `t:<metadata.created>|<metadata.title>` (title cut at 200 characters);
  - `null` when the tape names none of the three, and then nothing is remembered.
  - `codeKey(code)` gives `code:<code>`, for a sent tape known only by its link.
- `recordPage(store, key, index, total, now)` stores the 1-based `page = index + 1` with `of = total` and the `at`
  ISO time, only when `1 ≤ index < total` (integers). Otherwise it returns the same store. It is immutable, and
  re-recording a tape refreshes its `at`.
- The cap is `RESUME_CAP = 50`, and the least recent `at` is dropped first.
- `clearTape(store, key)` removes one tape. When there is nothing to clear it returns the same store, so nothing is
  written.
- `resumePoint(store, key, total)` gives `{ page }`. It gives `null` when the tape has no place, or when the stored
  `of` differs from `total` (the tape has changed).
- `latestResumed(store, tapes)` gives the key with the most recent valid place. The shelf uses it on arrival.
- `sanitizeResume(raw)` accepts a JSON string or a parsed value. It drops anything that is not version 1, and any
  entry that has:
  - a page or `of` that is not an integer, or a page outside `2…of`;
  - an `at` that is not a real time;
  - any extra field;
  - an empty or overlong key.
  It never throws.
- `serializeResume(store)` writes the envelope.

### `src/components/player/Player.tsx`
- Three optional props:
  - `startPage` (1-based): the page Tap to Begin opens on, when the shelf chose it;
  - `resumePage` (1-based): a remembered place the cover offers when nobody chose a start page;
  - `onPage(place)`, with `place` = `{ index, total, ended }`.
  `__ssyncPlayer` is not extended.
- The cover row (`[data-pl="resume"]`) appears only when there is an offer:
  - it sits under the unchanged gold "Tap to Begin": the line "You stopped at page N." (Fraunces 700, 20px, paper),
    then a full-width ghost kit `BigButton` "Pick up where you left off";
  - activating the ghost calls the same `begin()` as Tap to Begin (the iOS audio unlock), with the page;
  - Tap to Begin still opens page 1;
  - with no offer the cover is exactly what it was before this ticket.
- `onPage` fires from an effect once `started` is true: once per settled page (`index`), and once for the end card
  (`ended: true`). Nothing is reported on the cover. Read it again reports page 1, which `recordPage` ignores.

### `src/components/player/ReadRoom.tsx`
- **Keys, the same from every door.** Each ready state carries a `placeKey`:
  - a link: `tapeKey(manifest, ?story=)`;
  - a shelf tape: `tapeKey(manifest, entry.shareCode)`, where the tape's own shareUrl wins, then the code, then
    created + title;
  - the demo and files: `tapeKey(manifest)`;
  - a sent tape on the shelf: `code:<its code>`, the key its link door produces.
- **Recording.** `keepPlace` runs `recordPage` for each reported page and `clearTape` for the end card. It reads and
  writes `ssync-resume` in try/catch. A store with no tapes left removes the key.
- **The cover's offer.** A link, the demo and a file read `resumePoint` when the tape becomes ready, and pass it as
  `resumePage`. The shelf always chooses:
  - "Pick up where you left off" passes `startPage = N`;
  - "Start again" and "Play this tape" pass `startPage = 1`;
  - so a tape opened from the shelf never shows the cover's offer.
  - A sent tape plays through its link. The shelf's choice rides along in a ref keyed to that code and is consumed
    once by the `?story=` resolver.
- **The band.** When the selected tape has a valid place, the band shows, under T20a's mono label-yellow line:
  - **"You stopped at page N."** (`.rr-band-resume`, Fraunces 700, 22px, paper);
  - a gold **"Pick up where you left off"** (lucide `Play`);
  - a ghost **"Start again"**;
  - T20a's "Pull the tape out" (own tapes) or T20b's "Take it off this shelf" (sent tapes) stays as the last action.
  Without a place, the band is T20a's, with "Play this tape".
- **Default selection.** On arrival (no current selection), the shelf selects the tape stopped in most recently
  (`latestResumed`), else T20a's first tape. A selection made during the visit is kept when the room comes back from
  the Player. The selected face is brought into sight inside the shelf's own horizontal scroller, which matters on
  phones when the resumed tape is far along. The page itself never scrolls.
- **Forgetting.**
  - The end card clears the tape's key.
  - A pull-out (after `deleteBook` succeeds) clears every key the tape could have been remembered under, through
    `resume-store.ts` `placeKeysOfTape`: the link code(s), the `t:` key from the played and the stored manifest,
    and `code:<library id>`.
  - "Take it off this shelf" and the missing state's "Take it off this shelf" clear `code:<code>`.
  - "Start again" clears the old place once the tape has begun (round 1).
  - The Studio's "Pull the tape out — delete everything" clears every key of every copy (round 1, see above).

## Deviations from the reference, and why

- **The band shows a family tape's place, not "On Sunday you heard all 8 pages."** The rendered s07 line is
  listening history (a weekday and "heard"), which HANDOFF §7 forbids. The brief's own copy list carries the built
  line: "You stopped at page 5." / "Pick up where you left off" / "Start again".
- **No FEATURED art and no per-page strip.** The band art belongs to the curated house catalog (Idea). The 8-segment
  strip under the s07 band is a record of the pages heard. The place is shown only as words.
- **The house tape's place is offered on its cover**, not in a catalog band. The house tape is a door in its own row
  (T20a).
- **The band keeps a destructive third action.** "Pull the tape out" (own tape) or "Take it off this shelf" (sent
  tape) stays after the two reading choices. The reference band is the house tape's, which cannot be deleted. Here a
  tape's band is the only place to remove it.
- **Buttons use T20a's band size** (48px, radius 14), not s07's 40px pills, so the band reads the same with or
  without a place.
- **The cover line is Fraunces 700 at 20px** (the band is 22px). The cover has no reference. 20px keeps the 88px gold
  Tap to Begin dominant in the 460px cover column and on a 390px phone.
- **Three Player props, not two.** The ticket's "two props" were a start page and a page callback. The cover's offer
  needs the remembered page separately from a page the shelf chose, so there is a third optional `resumePage`. With
  none of the three, the Player is exactly as before.
- **`tapeKey` can be null**, for a tape with no link, no `created` and no title. That tape has nothing to be known by
  across visits, so it is not remembered rather than sharing a key with every other untitled tape.
- **A pull-out clears every key the tape could be under** (its code, its `t:` key and `code:<library id>`), not only
  the shelf door's key, so a tape that was also opened from a file leaves no place behind.
- **The selected face is scrolled into sight inside the shelf** (phones). T20a always selected the first face. A
  resumed tape can be fifth on a 375px ledge.
- **Page 1 is never a place** (ticket rule). Going back to page 1 and closing keeps the earlier place.
- **"Start again" forgets the old place once the tape has begun** (round 1, the review's polish). The ticket only
  says it starts at page 1. A band that still said "You stopped at page 3." after the listener chose to start over
  and closed on page 1 contradicted that choice. Choosing alone (the cover, before Tap to Begin) keeps the place.
  The cover's own Tap to Begin (a link, the demo, a file) still keeps it, as the ticket's test 3 requires.
- **PRIVACY.md row, widened** (round 1). The ticket's verbatim "Deleted by" cell was "finishing the tape, pulling it
  out, taking it off the shelf, or clearing browser data". It now reads "finishing the tape, pulling it out or
  deleting the story, taking it off the shelf, or clearing browser data", so it names the Studio's delete too. The
  row is new in this ticket, so the change is not an edit to a shipped row.
- **A new file outside the ticket's file list**: `src/components/player/resume-store.ts` (round 1, as the review
  proposed). The storage wrappers had to be shared with the Studio, and `resume.ts` must stay pure.
- **A sent tape opened by its link is keyed by that link's code** (round 1). The ticket says a link passes its
  `?story=` code to `tapeKey`, where the tape's own shareUrl wins. For someone else's tape that could differ from
  the shelf's `code:<code>`, so the link door now uses the shelf's key.
- **Short phones tighten the cover's rhythm** (round 1, `resume.css`, ≤ 600px tall, offer present only), so the
  gate fits 320×568.

**2026-10-26 · T21 · Resume keeps one page number per tape, on this device; the shelf chooses, every other door offers;
deleting the story forgets it everywhere.**

- **What is kept.** `ssync-resume` = `{ v: 1, tapes: { <key>: { page, of, at } } }`:
  - 1-based, page 2 onward;
  - capped at 50 tapes, with the least recently stopped dropped;
  - sanitized on every read (any other field drops the entry).
  Nothing else about reading is stored or sent: no history, no "heard", no counts, no weekdays.
- **The key.**
  - `code:<code>` from the tape's own `signature.shareUrl` `?story=`, else from the code it was opened by (a link's
    `?story=`, a shelf tape's library share code);
  - else `t:<metadata.created>|<metadata.title>`;
  - no key (not remembered) when a tape has none of these.
  - A sent tape on the shelf is `code:<its code>`, the key its link produces.
- **Who decides where it opens.**
  - The shelf always chooses: "Pick up where you left off" → N, "Start again" and "Play this tape" → 1. Its cover
    offers nothing.
  - A link, the house tape and a file offer a valid place on the cover ("You stopped at page N." + a ghost "Pick up
    where you left off", which is the same audio-unlock tap). Tap to Begin is always page 1.
  - A place whose `of` differs from the tape's page count is stale and never offered.
- **Forgetting.**
  - The end card clears the place.
  - Deleting a story clears every key any copy of it could be under: its link codes, `code:<library id>`, and
    `t:<created>|<title>`, both as stored and as played. This applies to the shelf's pull-out and to the Studio's
    "Pull the tape out — delete everything". One shared, SSR-safe helper does it,
    `src/components/player/resume-store.ts`, and `resume.ts` stays pure.
  - "Take it off this shelf" clears the sent tape's `code:` key. A tape someone sent is kept under that link code
    at every door.
  - "Start again" clears the old place once the tape has begun.
  - Clearing browser data clears it all.
  - PRIVACY.md "What is stored where" has the row.
- **Arrival.** The shelf selects the tape stopped in most recently, else the first. The Player reports settled pages
  and the end card through `onPage`; the Read Room alone writes storage.
