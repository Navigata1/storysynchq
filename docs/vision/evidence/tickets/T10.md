## What was built

- **`src/components/player/music-plan.ts` (new, pure).** No React, no `@/`, no DOM; relative imports only. It
  answers, for any page of any manifest:
  - `pageMood(manifest, page)`: the mood, or `null` for silence. This is the Player's old private
    `moodTokens` + `pageMood` logic, moved here unchanged.
  - `pageCrossfadeSeconds(page)` / `parseCrossfadeSeconds(value)`: the crossfade into the page.
  - `pageMusic(manifest, page)` gives `{ mood, crossfadeSeconds }`.
  - `musicPlan(manifest)` gives that pair for every page, in page order. T12's liner notes and T24's per-page
    moods can use it.
  - Constants: `DEFAULT_CROSSFADE_S` (1.6, re-exported from the bed, so the default has one source),
    `MIN_CROSSFADE_S` (0.05, the bed's own floor) and `MAX_CROSSFADE_S` (10).
  - Accepted durations: `^(\d+(\.\d+)?|\.\d+)\s*(ms|s)?$`, case-insensitive, after a trim. A bare number counts
    as seconds, the way `parseDuration` reads it. Anything else is 1.6: a non-string, `"soon"`, `""`, `"-2s"`
    or `"2s please"`. A valid value is clamped to 0.05–10 s.
- **`src/lib/audio/music.ts`.**
  - `CROSSFADE_S` became the exported `DEFAULT_CROSSFADE_S` (still 1.6), and the new `MIN_CROSSFADE_S` (0.05)
    is exported beside it.
  - `MusicBed` gains the read-only `lastCrossfadeSeconds`, which is `null` until the first crossfade. It is set
    only when `setMood` really crossfades: a start from silence and a same-mood call leave it alone.
  - A non-finite seconds value now falls back to 1.6 instead of reaching the gain automation as NaN.
  - With no argument the bed behaves exactly as before.
- **`src/lib/audio/engine.ts`.**
  - `startMusic(mood, crossfadeSeconds?)` and `setMood(mood, crossfadeSeconds?)` pass the value to the bed. If
    it is omitted, `undefined` reaches the bed's default parameter, so the crossfade is 1.6 s as before.
  - New read-only getter `lastCrossfadeSeconds`.
  - New export `DUCK_DEPTH_DB = -20·log10(DUCK_FACTOR)` ≈ 12.04. It is derived from the existing factor; the
    behaviour is unchanged.
- **`src/components/player/Player.tsx`.**
  - The private `LooseTrack` / `moodTokens` / `pageMood` (54 lines) are deleted. The Player now asks the music
    plan for `mood` and `crossfadeS` (both memoised).
  - The music effect calls `engine.startMusic(mood, crossfadeS)`, which crossfades when a bed is running.
  - `window.__ssyncPlayer` gains `crossfadeSeconds()`, which reads `engine.lastCrossfadeSeconds`. Like the other
    members, it is a getter only.
  - The file-header rule 3 now names the music plan and `music.duration`.
- **`docs/format-spec.md` §4.** New bullet "Per-page mood and crossfade": `pages[].music.duration` is the
  crossfade into this page's mood; the default is 1.6 s; players MAY clamp. The bullet also states:
  - the reference player clamps to 0.05–10 s;
  - the duration belongs to the page being entered;
  - a bed starting from silence fades in on its own envelope.
- **`public/protocol/v2.schema.json`.** The only change is a `description` on `pages[].music` (object form)
  `.duration`: "Crossfade into this page's mood, e.g. "2s" or "450ms"; default 1.6 s; players MAY clamp". The
  structure is unchanged, and the file still parses (roundtrip test 7 is green).
- **`tests/fixtures/reader-tapes.ts` (new).** It holds:
  - `silentWavDataUrl()`, `libraryRow()` and `seedReaderTapes(page, rows)`. The seeder writes `ssync-library`
    once per tab from an init script, with a session marker so a reload does not re-seed.
  - The two T10 tapes, both original content:
    - "Four Kinds of Weather" (`PER_PAGE_MOOD_TAPE`): `"Wonder"` → `{ crossfade: "Hush", duration: "4s" }` →
      `"Rain"` → `"Wonder"`;
    - "The Quiet Middle" (`QUIET_MIDDLE_TAPE`): `"Calm"` → no music → `{ crossfade: "Joy", duration: "2s" }`.
  - Both tapes use silent WAV voices, `autoPlay: false`, the house demo pictures and one `voiceConsent` record.
  - Share codes are 32 hex characters, so a later share-code format check will not reject them.

## Deviations

- **None from the reference.**
- **One design choice the ticket left open.** `music.duration` governs crossfades between moods only. A bed that
  starts from silence (the first page, after a page with no music, or Music on) uses the bed's existing 2.5 s pad
  fade-in and does not count as a crossfade, so `crossfadeSeconds()` is unchanged. This keeps "null before any
  crossfade" literal. The Quiet Middle test pins it, and §4 of the spec says it in one clause.
- **`lastCrossfadeSeconds` survives Music off.** It is the last crossfade played, not the current state. Only
  `dispose()` clears it, because the bed itself goes.

## Decision log entry

**2026-10-25 · T10 · A page's `music.duration` is the crossfade into that page's mood; the Player reads it through a pure music plan.**

- **Where the answer lives.** `src/components/player/music-plan.ts` is the one place that says which mood a page plays
  and how long the bed takes to cross into it. The Player's private mood logic moved there unchanged, and a frozen copy
  in `tests/vision-music-plan.spec.ts` proves it.
  - Callers: the Player, T12's liner notes and T24's per-page moods.
  - Relative imports only, so Node tests import it.
- **The crossfade.**
  - **Whose duration.** The duration belongs to the page being entered, whichever way the reader turns. Going back
    6 → 5 on the house tape uses page 5's 1.6 s, not page 6's 3 s.
  - **Default.** 1.6 s. It has one source: the bed's exported `DEFAULT_CROSSFADE_S`.
  - **What parses.** A non-negative `"Ns"` / `"Nms"` / bare-seconds string, clamped to 0.05–10 s. Anything else is the
    default; for example, `"-2s"` is the default, not the floor.
  - **Starting from silence.** It is not a crossfade. The bed keeps its own pad fade-in, and the duration does not
    apply.
- **Engine and bed.**
  - `startMusic` / `setMood` take an optional crossfade in seconds; when it is omitted, the behaviour is unchanged.
  - Both expose a read-only `lastCrossfadeSeconds` (null before the first crossfade).
  - `window.__ssyncPlayer.crossfadeSeconds()` reads it. It is a getter only, and nothing leaves the device.
- **Duck depth.** The engine exports `DUCK_DEPTH_DB = -20·log10(DUCK_FACTOR)` ≈ 12.04, so the UI can print "12 dB"
  from the real constant (T09a, M5).
- **Spec and schema.** §4 of the format spec documents the rule, and the v2 schema's `duration` gains a matching
  description with no structural change.
