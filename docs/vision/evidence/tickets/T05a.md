## What was built
- **`src/app/globals.css`**:
  - `:root` now carries every SSYNC foundation token with the reference names and values:
    - Register A: `--ss-navy`…`--ss-ok`, 17 tokens.
    - Register B: `--ss-paper`…`--ss-shell-2`, 10 tokens.
    - Local additions, 10 tokens: kraft, tape-brown + both stops, crayon paper, red-ink, shell-hi, foot-1/2, slot.
    - The 8 `--mood-*` colours.
    - The 7 `--ss-layer-*` fills.
    - `--ss-ease`.
    - The three type stacks: `--ss-display`, `--ss-ui`, `--ss-mono`.
  - These are additive only. `--background`/`--foreground` and the `body` rule are untouched.
  - The existing `@theme inline` block now also declares `--color-ss-*` for every colour token, plus `--color-mood-*`, `--color-ss-layer-*`, `--ease-ss` and `--font-ss-display`/`-ui`/`-mono`. Tailwind 4 generates `bg-ss-navy`, `text-ss-ink`, `border-ss-ink`, `bg-mood-wonder`, `ease-ss`, `font-ss-display` and the rest wherever a later ticket uses them.
  - `--ss-tape-brown` is a gradient, not a colour, so it has no `--color-*` entry. Its two stops do.
- **`src/components/studio-kit/tokens.ts` (new, pure data, no `"use client"`)** exports:
  - `REGISTER_A`, `REGISTER_B`, `LOCAL`;
  - `MOOD_COLOR: Record<MoodName, string>`, keyed by the shared `MoodName` through a type-only import;
  - `LAYER_FILL: Record<PacketLayerName, string>`;
  - `SS_EASE`, plus `SS_FONT` (the three type stacks);
  - `TAPE` / `STUDIO`, built from the registers with the same keys and the same strings as before.
  - Hex case follows the brief, so `TAPE`, `STUDIO` and the layer fills keep their exact old strings.
- **`src/components/studio-kit/kit.tsx`**: `TAPE` and `STUDIO` are now `export { TAPE, STUDIO } from "./tokens"`. The header documents the tokens and the kit layout convention.
- **`src/components/studio-kit/kit.css`**:
  - Every solid colour that has a token now uses `var(--ss-*)`: ink, paper, label, red, gold, violet, navy, and `#ffffff` as `--ss-fg`.
  - Alpha tints such as `rgba(30, 26, 22, .07)` and off-token gradient stops such as `#fbbf24` / `#8b7bff` stay literal, because no token names them yet. T05b aligns the gradients.
  - Every transition curve, the `ease-out`s and the near-twin `cubic-bezier(0.2, 0.7, 0.3, 1)`, is now `var(--ss-ease)`. Durations are unchanged. See deviation 2.
  - `.sk-font-tape` / `-meta` / `-ui` read `var(--ss-display)` / `var(--ss-mono)` / `var(--ss-ui)`.
- **`src/app/layout.tsx`**:
  - Fraunces is the variable font: `weight` is omitted and `style: ["normal", "italic"]` is set.
  - IBM Plex Mono loads 400, 500 and 600.
  - The four next/font variable classes moved from `<body>` to `<html>`. This was required: `:root`'s `--ss-display: var(--font-fraunces), …` is substituted on `<html>`, and with the classes on `<body>` it computed to empty. See the decision entry. `body` keeps `antialiased`.
- **`src/components/protocol/layers.ts`**: the seven `fill`s come from `LAYER_FILL`, and the strokes from `REGISTER_B.ink` / `.red`. The strings are identical, so the SVG is identical.
- **`CLAUDE.md`**: one line under Project Structure `studio-kit/` records the kit layout convention and the tokens mirror.

## Deviations from the ticket and why
1. **The drift check compares resolved values, not raw strings.** The ticket's literal check is "`getPropertyValue(name).trim().toLowerCase()` equals the mirror's value". Next's CSS pipeline (Lightning CSS) re-serialises custom-property values on the way to the browser:
   - `rgba(255, 255, 255, 0.1)` arrives as `#ffffff1a`;
   - `#ffffff` arrives as `#fff`;
   - `cubic-bezier(0.22, 0.8, 0.24, 1)` arrives as `cubic-bezier(.22, .8, .24, 1)`;
   - a production minify may shorten further.

   So the raw string is not stable for 6 of the 53 tokens (the four line/glass tints, `--ss-fg` and `--ss-ease`). The test still reads the raw property, which must be non-empty and must equal the mirror verbatim for every 6-digit hex. For all tokens, it compares what the value **resolves** to: a probe styled with `var(--token)` against the same probe styled with the mirror literal, using `color`, `background-image` or `transition-timing-function`. Its failure power is shown by the mutation check. The mirror keeps the reference's own spelling, and `foundation.css` itself is the Node-side oracle.
2. **`cubic-bezier(0.2, 0.7, 0.3, 1)` also became `var(--ss-ease)`.** The criterion names "every `ease-out`", and cites "one easing family everywhere". The kit's transform/knob curve was a near-twin second family, so leaving it would keep two families. Durations are unchanged, and nothing static changes. The `sk-ring-pulse` *animation* (`ease-out`) and the VU meter's `linear` transition are deliberately left alone: the first is an animation, and the second is meter physics with JS-swapped durations.
3. **The font variable classes moved from `<body>` to `<html>`.** The ticket does not name this, but without it `--ss-display` / `--ss-ui` / `--ss-mono` on `:root` compute empty, because `var(--font-fraunces)` is undefined there, and anything later using `font-ss-display` would fall back to the browser default. `body` content inherits the same values, so nothing renders differently. This is also next/font's documented pattern.
4. **Extra exports:** `SS_FONT` (type stacks) and the `PacketLayerName` type. They are small, typed, and tree-shaken where unused.
5. **`kit.css` font classes now read the type tokens.** Their fallback tails changed from `Georgia, "Iowan Old Style", "Times New Roman"` to the reference's `"Iowan Old Style", Georgia`, and the mono tail lost `SFMono-Regular, Consolas`. The primary families and next/font's metric-matched fallbacks are first in both, so rendering is unchanged when the fonts load.

## Decision log entry
**2026-10-25 · T05a · SSYNC tokens live on `:root`; next/font variables sit on `<html>`.** The reference foundation tokens (`--ss-*`, `--mood-*`, `--ss-layer-*`, `--ss-ease`, `--ss-display/-ui/-mono`) are defined once, on `:root` in `src/app/globals.css`, and exposed to Tailwind 4 through `@theme inline` (`bg-ss-navy`, `ease-ss`, `font-ss-display` …). `src/components/studio-kit/tokens.ts` is the typed mirror, for SVG attributes, canvas and tests only. `tests/vision-tokens.spec.ts` fails if the CSS and the mirror resolve differently on `/`, `/read`, `/studio` or `/protocol`.

Because `:root` type tokens reference `var(--font-*)`, the next/font variable classes moved from `<body>` to `<html>`. A custom property is substituted where it is declared, so on `<body>` the type tokens computed empty.

The kit's layout convention: existing primitives stay in `kit.tsx`/`kit.css`, and each new shared component is its own `studio-kit/<Name>.tsx` (plus a scoped `<name>.css` when needed), imported from that file directly.

T05a is the only M0–M5 ticket that edits `globals.css`.
