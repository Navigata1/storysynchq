## What was built
- **`src/lib/storysync/tape-meta.ts` (new, pure, no DOM, no `@/` aliases).** This is now the only place that does runtime arithmetic and builds a tape label:
  - `parseDuration`, `formatClock` (moved here unchanged).
  - `estimateRuntimeSeconds(pages, defaultPauseMs = 3000)`: words ÷ 2.5 plus the sum of each page's `autoPause`. The default is 3 s and `ms` is honoured. No floor.
  - `estimateSeconds`: the Player cover's existing estimate, which is `estimateRuntimeSeconds` floored at 20 s. Behaviour is unchanged.
  - `narrationKind(pages)`: returns `READ-ALONG`, `AAC/M4A`, `WAV` or `RECORDED` (see the deviations section).
  - `runtimeLabel(manifest)`: returns `~m:ss`. Like the Player, it uses the manifest's `settings.accessibility.pauseBetweenPages` as the default pause. T20a's shelf can call it directly.
  - `tapeMetaLine(manifest)`: returns `SIDE A · <n> PAGE(S) · ~<m:ss> · <kind>`.
- **`src/components/player/timing.ts`** re-exports `estimateSeconds`, `formatClock`, `parseDuration` and `TimedPage` from tape-meta, so there is one source. `splitWords` and `wordIndexAtTime` stay where they were, and `Player.tsx` and `tests/wp-player.spec.ts` are untouched.
- **`src/components/landing/Landing.tsx`** (protocol section only). The component imports `public/demo/brave-little-star.ssync.json` as a static JSON import and builds a module constant from it: `HOUSE_TAPE = { title, author, meta: tapeMetaLine(houseTape) }`. The teaser renders `<TapeLabel title author meta>` from that constant. No house-tape string literal is left in the component. T06 can reuse `HOUSE_TAPE` / `houseTape` for the hero, which keeps to "no second reader of the demo manifest" (M1-PRD).

## Deviations from the ticket and why
1. **`narrationKind` has a fourth value, `RECORDED`.** The ticket names three outcomes but leaves one input unspecified: a page that has `audioUrl` but no `audioCodec`, and whose URL reveals no codec (an extensionless https URL, or a draft `data:audio/webm`).
   - The module first infers the codec from the URL: `.m4a`/`.mp4`/`.aac` or `data:audio/mp4|aac|m4a` → aac, and `.wav` or `data:audio/wav|wave|x-wav` → wav.
   - If neither the declaration nor the URL settles it, the kind is `RECORDED`. Neither `AAC/M4A` nor `WAV` would be true, and the whole point of T01 is that a label never makes a claim it cannot back.
   - The three outcomes the ticket specifies behave exactly as written. Test 10 pins the inference and the fallback.
2. **There are two estimators.** `tapeMetaLine` and `runtimeLabel` use `estimateRuntimeSeconds`, which has no floor. The Player cover keeps `estimateSeconds`, whose 20 s floor is unchanged because the ticket says "no behaviour change".
   - The two agree for any tape longer than 20 s, which includes the house tape at 106.6 s.
   - `tapeMetaLine` does read `settings.accessibility.pauseBetweenPages` as the default pause, the same way the Player does. For the house tape that value is `3s`, so the result does not change.

## Decision log entry
**2026-10-25 · Tape labels are derived, never typed (T01)** — The landing's protocol teaser printed a hand-typed `SIDE A · 8 PAGES · 4:32 · AAC/M4A` for the house tape. That tape has no recorded voice and runs about 1:47. All runtime and label arithmetic now lives in `src/lib/storysync/tape-meta.ts`:
- `estimateRuntimeSeconds`: words ÷ 2.5 plus the autoPause sum, 3 s default, `ms` honoured.
- `narrationKind` and `tapeMetaLine`.
- The Player's `timing.ts` re-exports `estimateSeconds` / `parseDuration` / `formatClock` from it. The Player cover keeps its 20 s floor.

The landing imports `public/demo/brave-little-star.ssync.json` statically, at build time with no runtime fetch. The teaser's title, author and meta all come from it, so the label now reads `SIDE A · 8 PAGES · ~1:47 · READ-ALONG`.

The narration kind is:
- `READ-ALONG` when no page has `audioUrl`.
- `AAC/M4A` only when every recorded page is AAC.
- `WAV` when any recorded page is WAV.
- `RECORDED` when a recorded page's codec is neither declared nor readable from its URL. A label never claims a codec on a guess.

The protocol rule sentence ("Published narration is always AAC/M4A …") stays: it is a rule about published tapes, not a claim about this one.
