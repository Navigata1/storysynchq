## What was built

- **`src/lib/storysync/consent.ts`** (new, pure: no DOM, no storage, no clock):
  - `recordedVoices(pages, byline)` returns the ordered, distinct voices of the pages that carry `text.audioUrl`.
    Each page's key is `text.voice?.trim()`, then `byline.trim()`, then `"narrator"` (`UNNAMED_VOICE`).
  - `consentDate(date)` returns `YYYY-MM-DD` built from `getFullYear` / `getMonth` / `getDate`. It never calls
    `toISOString`.
  - `consentRecords(voices, grantedBy, date)` returns `[{ voice, grantedBy, date }]` in voice order. It is typed
    `VoiceConsentRecord`, which is `SsyncSignature["voiceConsent"][number]` with `date` required.
- **`ParentGate.tsx`**:
  - The boolean `requireConsent` is replaced by `voices: string[]`, so a consent row exists exactly when
    `voices.length > 0`.
  - A new optional `onAuthorChange(author)` lets the Studio recompute the voices as "story by" is typed.
  - `onPass(author, consentedVoices)` is called only when every row is ticked. The Enter path is guarded in
    `submit`, as well as the disabled Continue.
  - One voice renders the old row unchanged: `id="studio-gate-consent"`, the reference sentence, no name, and the
    sub-line beneath it.
  - Several voices render one row each, with ids `studio-gate-consent-1…n`. Each row has a mono voice label
    (`data-studio="consent-voice"`, IBM Plex Mono 11 px, amber) above the same sentence and a hairline between
    rows. The sub-line is said once, beneath the last row.
  - The ticks follow the voice list. When "story by" renames the voice it credits *in place* (same recordings,
    new name), the ticks stand. Any other change clears every tick, so the grown-up is asked again
    (`renamedInPlace`). Examples are the byline folding into another voice, or splitting back out of one.
  - The panel gained `max-h-full overflow-y-auto overscroll-contain`, so a taller gate scrolls inside itself on a
    short phone (see Deviations).
- **`Studio.tsx`**:
  - `gateAuthor` state is reset when "Finish my story" opens the gate.
  - The gate gets `voices={recordedVoices(state.manifest.pages, gateAuthor)}` and `onAuthorChange={setGateAuthor}`.
  - `runPublish(author, consentedVoices)`:
    - collects `recordedVoices(publishedPages, author)`;
    - refuses to assemble if any recorded voice is missing from `consentedVoices` (unreachable through the gate,
      and a guard for later callers);
    - writes `consentRecords(voices, "parent/guardian", consentDate(now))`;
    - with no recorded voice, deletes `voiceConsent` so no stale record can ride along from an earlier publish.
  - `consentRef` is now `string[]`, the consented voices, and the publish card's retry reuses it.
  - Ownership, rights and `shareUrl` are untouched (`© <year> <author>` / `© <year>`, `"personal use"`, the
    spread of the existing signature).
  - The `storyHasNarration` import is no longer used in this file and was dropped.

The gate's layout and styling are otherwise unchanged, because T14 redesigns the gate. Only Tailwind utilities were
used, and no stylesheet was edited.

## Deviations from the reference, and why

- **The rest of the gate is not redrawn here.** The kicker ("BEFORE ANYTHING LEAVES THIS …"), the italic trust
  line, the 07 band badge, the answer's ✓, the pencil glyph, the sub-line indented under the sentence column, the
  520 px panel, the seven-layer sheet and the stamp are all absent. The ticket says the layout stays as it is,
  because T14 redesigns the gate and owns every one of these.
- **Two-voice rows have no reference.** s04 draws one voice only, and the callout calls a record per voice "next".
  The rows reuse the reference sentence verbatim under a mono voice label, so the copy is not invented. The label
  is in mixed case, not uppercase, because it is a person's credit ("Mia, age 4 — with Mom"), and it wraps rather
  than truncates so the full name a parent consents to is always visible.
- **The gate panel scrolls inside itself** (`max-h-full overflow-y-auto`). A second row adds about 90 px. On
  short phones the bottom-anchored panel already lost its title off the top at 320×568 before this ticket, and
  with two voices it would lose the question as well. This is one class string on the panel, not a layout change.
- **Ticks and a changing "story by".** Renaming the byline voice keeps its tick; folding or splitting voices clears
  all ticks. The ticket does not say what happens when the byline is edited after ticking. This rule keeps
  today's single-voice behaviour (tick, then type the name) and never carries a tick to a set of recordings the
  grown-up did not tick.
- **A tape with no recorded voice drops any `voiceConsent` left in the draft's signature.** The old code carried it
  over from an earlier publish. A consent record for a voice that is no longer on the tape is false data, and
  the ticket requires "no `voiceConsent` key".
- **The Creator refuses to assemble when a recorded voice has no consent**, with the error "Every recorded voice
  needs a grown-up's consent first." The gate makes this unreachable today. It is the COPPA invariant enforced at
  the writer, for T15/T18/T14, which add new routes into `runPublish`.

## Decision log entry

**2026-10-25 · T04b · The Creator writes one consent record per recorded voice, dated with the device's local
calendar day.**

- A recorded voice is keyed per page by `text.voice`, then "story by", then "narrator". `recordedVoices` returns
  them distinct and in page order (`src/lib/storysync/consent.ts`). The gate asks once per voice and the publish
  writes `consentRecords(voices, "parent/guardian", consentDate(now))`.
  - With one voice, the gate is exactly s04's row (`#studio-gate-consent`).
  - With several, each row carries the voice's name over the same sentence, and Continue (and Enter) waits for
    every tick.
  - A tape with no recorded voice carries no `voiceConsent` key.
- **M0-PRD Open Question 6 (per-voice ticking vs one checkbox listing the voices): per-voice ticking.** Consent to
  one recording is not consent to another (M0 story 9), and per-voice rows map one-to-one onto the records the
  file carries. Renaming the "story by" voice keeps its tick (same recordings, new credit). Any change in which
  recordings a row stands for clears every tick.
- **M0-PRD Open Question 7 (which day is "the date"): the consenting device's local calendar date.** It is built
  from `getFullYear` / `getMonth` / `getDate`, never `toISOString`, so 11:30 pm on Oct 19 in Los Angeles writes
  `2026-10-19` although UTC says Oct 20. It is the day the grown-up would name, and it matches the stamp's "OCT 19
  2026".
- The writer enforces the gate: `runPublish` refuses to assemble a tape with a recorded voice missing from the
  consented list.
