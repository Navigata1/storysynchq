## What was built

### `src/components/player/sent-to-you.ts` (new, pure; relative imports only)
- `SENT_KEY = "ssync-sent-to-you"` holds `{ v: 1, tapes: SentTape[] }`.
  `SentTape = { code, title, author, narrator?, pages, runtime, addedAt }` and nothing else.
- `SHELF_VISIT_KEY = "ssync-shelf-visit"` holds one ISO time.
- `sentFacts(code, manifest)` gives what a reference keeps of an opened tape: the code, plus `labelFacts` (T20a's
  reading: title, author, `~m:ss` runtime), `metadata.narrator` and the page count. Never a picture, words, a voice
  or a URL.
- `rememberSent(list, entry, now)`:
  - dedupes by code: an existing code keeps its `addedAt` and takes the fresh label facts;
  - a new code arrives at `now` (a Date, epoch ms or ISO string);
  - the list is capped at `SENT_CAP = 30`, dropping the oldest arrival;
  - an entry that is not a valid reference changes nothing.
- `forgetSent(list, code)` removes that code only.
- `sanitizeSent(raw)` takes the stored string or the parsed envelope. It drops:
  - malformed entries;
  - entries carrying any field outside the seven (a picture, words, a URL), dropped whole, not trimmed;
  - codes that are not 16–64 lowercase hex.
  A repeated code keeps its first entry, and the result is capped. Bad JSON or another version gives an empty list.
  It never throws.
- `serializeSent(list)` writes the envelope (sanitized again on the way out).
- `ownKeys(rows)`: library rows → `{ ids, codes }`.
- `libraryIdOf(code, manifest, rows)` gives the row that *is* the opened tape:
  - by its id or share code;
  - or, because a signed-in cloud row carries no share code, by the tape's identity: `metadata.created` to the
    millisecond + title + page count + Signature layer. A tape with no `created` is matched by code or id only.
- `isOwnTape({ id, code }, ownIds, ownCodes)` is true when the id is one of yours, or the code is one of your codes
  (or one of your ids: older builds handed the id out as the code, and the device lookup still accepts it).
- `isNewSince(tape, previousVisit)` is `addedAt` strictly after the previous visit. With no previous visit it is
  never NEW.
- `orderSent(list, previousVisit)` puts NEW first, then the newest `addedAt`.
- `sentMetaLines` / `sentMeta(tape)` give "FROM <AUTHOR> · N PAGE(S) · ~m:ss", upper case. It says "PAGE" for 1,
  and leaves out "FROM …" when the author is empty.

### `src/components/player/ReadRoom.tsx`
- **Remember on resolve.** `?story=<code>` → `loadTapeByCode` (T15's resolver, unchanged). Then, *before* the cover
  shows, `rememberIfSent`:
  - it reads this device's library and, when `isCloudEnabled()` and a grown-up is signed in, their cloud library
    (the same two reads the shelf makes);
  - if `isOwnTape({ id: libraryIdOf(…), code })` it does nothing. A device-library hit is always yours;
  - otherwise it writes `rememberSent(readSent(), sentFacts(code, manifest), new Date())`;
  - it never throws: remembering is a convenience and the tape plays either way.
  A cancelled resolve (React's dev double-effect) remembers nothing.
- **NEW.** The first effect on mount reads `ssync-shelf-visit` into a ref (the previous visit) and writes the
  current time.
  - A ref guard keeps React's dev double-effect from reading the time it has just written.
  - The previous visit is held for the component's life, so the stamp stays for the whole visit, including after
    closing a tape.
- **The shelf** is now `ShelfItem[]`:
  - `{ kind: "sent", key: "sent:<code>", tape, isNew }`, ordered by `orderSent`;
  - then T20a's own entries `{ kind: "own", key: id, entry }`, unchanged.
  A reference whose code turned out to be yours is not shown as sent.
- **A sent face** is a `ShelfTape` in the same "Your tapes" radio group, with:
  - `data-sent="true"`, `data-tape-id=<code>`, no inset;
  - the meta in two lines ("FROM GRANDMA ROSE" / "1 PAGE · ~0:08", with the drawn-hidden " · " separator T20a
    uses, so its text is one line);
  - `newStamp` when it is NEW;
  - `ledgeLabel="Sent to you"` (upper case by CSS);
  - the accessible name `<title>` or `<title>, new`, described by the meta and the label.
  Arrow, Home and End keys walk across sent and own tapes alike.
- **The band for a sent tape:**
  - "Play this tape" runs `router.push("/read?story=<code>")`: the tape is resolved by its link, never from a stored
    copy;
  - the pull-out is replaced by a ghost **"Take it off this shelf"**. One press calls `forgetSent` (the key is removed
    when the list is empty), takes the face off, selects and focuses the next tape (so a repeated Enter cannot take
    off a second tape), and shows the status line **"Taken off this shelf. Only the person who made it can delete the
    tape itself."** ("Taken off this shelf." in bold, as "Pulled out." is).
- **Missing state.** When a link resolves to nothing, `remembered` records whether the code is on the list. If it
  is, a ghost **"Take it off this shelf"** follows the shipped buttons. It forgets the code and returns to the chooser.
- **Back to the shelf.** A link this visit opened from the shelf (`openedFromShelf`) goes back to `/read` on Close or
  on take-off (`router.back()`), not to `/`. Any other link keeps the shipped exit (`/`).
- Unchanged: own tapes, selection, the band, the pull-out and its line, `?demo=1`, the file door, T18's reply. A tape
  opened by a link is `origin: "share"`, so a sent tape still offers "Send a thank-you back".

## Deviations from the reference, and why

- **No picture inset on a sent tape** (M4-PRD OQ 2). A reference keeps the link code and label facts only. A cached
  thumbnail would be a copy the maker's one-tap delete could not reach.
- **"SENT TO YOU" is a plain mono label** (fg-2, 11px, 0.14em, upper case by CSS), not s07's violet "Sent to you ·
  Next" status chip. Everything M4 builds is shipped, so no status chip (brief LOCAL 15, M4-PRD Notes). It sits
  under each sent tape rather than once under the row, so it always names the tape above it.
- **`~m:ss`**: the runtime is T01's read-along estimate (`runtimeLabel`), as on every shelf face (M2-PRD OQ 3).
- **The NEW stamp's radius is 7px** where foundation `.ss-stamp` says 8px. At 11px type and 3/2px padding, 8px reads
  as a pill against the render; 7px matches the drawn corner.
- **Close from a link opened off the shelf returns to the shelf** (`router.back()`), not to `/` as other links do.
  Without it, playing a sent tape and closing it would land on the landing page, unlike every other shelf tape.
- **Ownership of a signed-in cloud tape is decided by identity** (`metadata.created` to the ms + title + page count +
  Signature), because cloud library rows carry no share code and `loadTapeByCode` returns only the manifest. A
  family's own copy that kept the original's `created`, title, pages and Signature would count as theirs and not be
  remembered. That is harmless: they hold the tape itself.

## Decision log entry

**2026-10-26 · T20b · Sent to you keeps a link, not a tape; NEW means "received since your last look at the shelf".**

- **What is kept.** A tape opened from someone else's link stays on this device's shelf as a reference:
  `ssync-sent-to-you` = `{ v: 1, tapes: [{ code, title, author, narrator?, pages, runtime, addedAt }] }`, capped at 30
  (the oldest arrival goes), sanitized on every read (an entry with any other field is dropped whole). Never
  pictures, words, voices or URLs. The maker's delete therefore still removes every copy: the reference just resolves
  to nothing.
- **Yours or sent.** A resolved tape is yours, and never remembered, when its id or code is in this device's
  library or, signed in, in your cloud library. Cloud rows carry no code, so for them the match is the tape's
  identity: `metadata.created` to the ms, title, page count and Signature. The decision is made before the cover
  shows, and nothing is sent to decide it.
- **On the shelf.** References stand first on the same "Your tapes" ledge (NEW first, then newest), as radios with
  `data-sent`, no picture, the meta "FROM <AUTHOR> · N PAGE(S) · ~m:ss" and "SENT TO YOU" under the ledge.
  - "Play this tape" opens `/read?story=<code>`, and Close returns to the shelf.
  - "Take it off this shelf" forgets the reference in one press, with the line "Taken off this shelf. Only the
    person who made it can delete the tape itself."
  - A remembered dead link's missing state offers the same button.
- **NEW.** `ssync-shelf-visit` (one ISO time) is read once per visit on mount and rewritten. A reference added
  strictly after the previous visit is stamped NEW for the whole visit. Own tapes are never stamped.
- **Kit.** `ShelfTape` gains `newStamp` (tape-red NEW, −6°, in T20a's stamp slot) and `ledgeLabel` / `ledgeLabelId`
  (a mono label under the ledge).
- **PRIVACY.md** gains the two "What is stored where" rows.
